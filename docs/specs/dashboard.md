# 规格：Dashboard

本文是 [DESIGN.md](../DESIGN.md) 第 9 节的实现细节。

## 1. 技术与结构

- React 19、Vite、TypeScript、TanStack Router（文件路由）、TanStack Query、TanStack Table、shadcn/ui（Radix，用到 dropdown-menu、popover、dialog 等几个组件，源码在 `src/components/ui/`）、Tailwind v4、zod（校验 URL 查询字符串）、Biome。表单（扫描表单、筛选）都是简单的受控组件，没有用 react-hook-form；Playwright 还没有接入。
- API 客户端由 `@hey-api/openapi-ts` 根据后端导出的 OpenAPI 生成到 `src/client/`，不手改。接口有变化时：`cd backend && uv run python scripts/export_openapi.py`（写出 `frontend/openapi.json`，需要设置 `DATABASE_URL` 和 `DATABASE_SCHEMA`），再 `cd frontend && npm run generate-client`。导出时把 FastAPI 生成的 operationId 缩短成函数名。
- 构建产物由后端的 `app.frontend(<BASE_PATH>, directory=…, fallback="index.html")` 托管（目录由 `FRONTEND_DIST` 指定，默认是镜像里的 `/app/frontend/dist`，本地是 `frontend/dist`）。路径前缀在构建时由 `BASE_PATH` 决定（Vite `base`，默认 `/aws-inventory`），路由和 API 客户端都用 `import.meta.env.BASE_URL`；开发时 Vite 把 `/aws-inventory/api` 代理到后端（`API_URL`，默认 `http://localhost:8000`）。

### 1.1 路由

| 路径 | 页面 |
|---|---|
| `/` | 概览 |
| `/resources` | 资源列表（筛选条件都在查询字符串里） |
| `/resources/$id` | 资源详情 |
| `/accounts` | 账号列表 |
| `/accounts/$accountId` | 账号详情 |
| `/scans` | 扫描（当前状态 + 扫描记录） |
| `/scans/$id` | 扫描详情 |
| `/tasks/$id` | 任务详情（含日志） |

### 1.2 全局布局
- 顶部一行：产品名、导航（概览、资源、账号）、右侧「管理」菜单（扫描）、全局搜索框、语言切换、亮色 / 暗色切换。
- 全局搜索：输入 ARN（以 `arn:aws` 开头）时跳到 `/resources/<ARN>`，详情页用 `GET /resources/lookup` 解析：一个账号就直接显示，多个账号（共享 AMI）先列出账号让用户选；输入其他内容时跳到资源列表，并带上 `q`。
- 语言、亮色 / 暗色、配色记在浏览器的 localStorage（`locale`、`theme`、`palette`），`public/theme-init.js` 在页面渲染前先应用，避免闪一下。

### 1.3 多语言和配色的实现
- **多语言**：自己写的一个很小的带类型检查的 i18n（`src/i18n/index.tsx`，约 60 行），没有用 react-i18next：界面只有一组扁平的文案、两种语言、简单的复数，不值得多一个运行时依赖。文案放在 `src/locales/zh-CN.json` 和 `en.json`，键在编译时检查，两个文件的键必须完全一致；插值写 `{name}`，数字自动加千分位；文案里用 ` | ` 分隔单数和复数（英文用）。后端返回的错误按 `code` 找 `error.<code>` 文案，找不到才用通用文案。
- **配色**：三套，都是一个主色加共用的暖灰，色值和对比度见 `frontend/PALETTES.md`：**黛绿**（`dai-lv`，默认）、**黛蓝**（`dai-lan`）、**胭脂**（`yan-zhi`）。在地址后面加 `?palette=dai-lan` 切换，选择会记在 localStorage；写在 `<html data-palette>` 上，亮色和暗色各有一组。三套都实现了，最终保留哪一套还没有定。

## 2. 数据表格组件（`components/data-table/`）

资源列表、账号列表、扫描记录、任务列表都用这一个组件。

- **列由后端决定**：调用 `GET /columns`，得到列定义，生成 TanStack Table 的列。
- **筛选控件按列类型自动生成**：

| 列类型 | 筛选控件 | 查询参数 |
|---|---|---|
| `text` | 输入框（包含匹配） | `attr.<key>=…` |
| `enum` | 多选下拉，选项和数量来自 `GET /resources/facets` | 重复的 `attr.<key>=…` |
| `number` | 最小值 / 最大值 | `attr.<key>.gte` / `.lte` |
| `bool` | 是 / 否 / 全部 | `attr.<key>=true\|false` |
| `datetime` | 开始 / 结束时间 | `.gte` / `.lte` |

- 筛选、排序、分页全部在服务端执行（`manualFiltering`、`manualSorting`、`manualPagination`）。
- 状态全部同步到 URL 查询字符串，可以收藏和分享：`page`、`pageSize`、`sort`、`q`，以及一个 `f` 对象保存所有列筛选（值是字符串、字符串数组，或 `{gte, lte}`）；和默认值相同的不写进地址。请求后端时再把它翻成 API 的参数：类型专属列加 `attr.` 前缀（用列的 `scope` 判断，所以和通用列重名的 `status` 不会混淆），范围写成 `.gte` / `.lte`。当前类型不认识的筛选会被忽略，不会让页面报错。
- 可以显示 / 隐藏列、调整列宽（保存在浏览器本地）；表头固定。
- 账号列表、扫描记录、任务列表的列在前端写死（它们是固定的小表）；只有资源列表的列来自 `GET /columns`。
- `mono = true` 的列用等宽字体；ID 和 ARN 支持一键复制。

## 3. 页面

### 3.1 概览
- 主体是一个大的搜索框（和全局搜索相同的行为）。
- 两个数字：资源总数（「128,430 个资源」）、账号数（「1,024 个账号」），各自链接到资源列表和账号列表。有无法访问的账号时另起一行「其中 12 个无法访问」，点击跳到筛选好的账号列表（`没有读取权限` 和 `无法获取凭证` 两种状态）。
- 两个分布：按资源类型、按环境，横向条形；点击任意一项跳到筛选好的资源列表。

### 3.2 资源列表
- 左侧：账号、EIM、BA、环境、区域、类型、标签（有 / 缺少 / 等于）的筛选，选项后面带数量。
- 顶部：搜索框、已选筛选条件（可逐个移除，「清除全部」）、结果数（「共 1,342 个资源」）、「导出」（选择 CSV 或 JSON Lines）。
- 表格：没选类型时显示通用列；只选了一个类型时，自动加上这个类型的专属列，并在表头提供列筛选。「关联资源」一列显示关联数量。
- 状态标记只在不正常时显示：「可能已删除」「已删除」「数据过期」；正常资源不加任何标记。
- 默认不显示已删除的资源；「包括已删除」是状态筛选里的一个选项。

### 3.3 资源详情
- 标题区：资源名称（没有名称时显示资源 ID）、类型、异常状态（如有）、「刷新」按钮。
- 刷新：调用 `POST /resources/refresh?wait=20`。等待时按钮显示加载状态；202 时显示「刷新中」并轮询任务；失败时在标题区下方用一行文字说明原因（比如「没有读取权限」），不弹框。
- 基本信息：ARN（可复制）、账号（名称，悬停显示 ID）、EIM、BA、环境、区域、首次发现时间。
- 「更新于 3 分钟前」：悬停显示具体时间和来源（「来自 AWS Config」/「实时查询」）。
- 标签：键值表格。
- 关联资源：按关系名分组，点击跳转；库里没有的显示为灰色、不可点击。
- 配置：Config 格式的 JSON 查看器，可以折叠、展开、在其中搜索。
- 实时数据：只有存在 `live` 时显示，标题写明观察时间。

### 3.4 账号
- 列表列：名称、ID、环境、EIM、BA、资源数、状态、上次扫描时间。状态只在不正常时显示文字：「没有读取权限」「无法获取凭证」「部分无权限」；已移除的账号显示「12 天后清理」。默认只列活跃账号，勾选「已移除的账号」（对应 `active=false`）才显示被移除的。
- 详情：
  - 基本信息和状态（直接写原因，不显示错误代码）。
  - 区域：已扫描的区域；「已开启，未扫描」的区域单独列出。
  - 「区域 × 类型」格子：每格一种状态（正常 / 失败 / 没有权限 / 数据过期 / 未扫描），悬停显示时间和原因。格子来自 `GET /accounts/{id}/coverage`，没有扫描记录的组合显示为「未扫描」。
  - 「扫描」按钮：扫描这个账号的所有区域和类型，提交后跳到这次扫描的详情。

### 3.5 扫描（管理）
上半部分是当前状态，按排查顺序排列：
1. 全量扫描进度：「已完成 612 / 1,024 个账号，预计 16:40 完成」，下面一条进度条，点击跳到这次扫描的详情；还没有账号完成时没有预计时间，只写「已完成 0 / 1,024 个账号」。比计划慢时显示「比计划慢了」，**不写具体时长**：`GET /scans/summary` 只返回 `behindSchedule`，不返回计划完成时间。
2. 任务积压：按需和定时分开，「排队 34 个，最早的等了 2 分钟」；只显示有排队任务的一行。
3. 最近 24 小时的失败：按原因分组，每组一句白话说明和处理建议（文案见 [scanner.md](scanner.md) 第 9 节），点击跳到**最近一次扫描**（正在跑的全量扫描，没有就是扫描记录里最新的一条）的任务列表，并按这个原因筛选：目前没有跨扫描的全局任务列表接口，任务列表只能在某次扫描下查看。
4. 可能已删除的资源：数量和列表，每行「再检查一次」（调用刷新接口，参数是这条记录的账号、区域、类型和资源 ID），列表放不下时链接到状态筛选为「可能已删除」的资源列表。
5. 数据异常的范围：每行「重新扫描」和「确认是真实变化」。后者是全产品唯一的二次确认，确认框写明「确认后，这些资源会逐个实时查询，确实不存在的才会标为已删除」。

没有问题的区块整个不显示，不放「一切正常」这类占位文字。

下半部分是扫描记录：时间、触发方式（定时 / 手动 / 调用方名称）、范围、状态、结果（「新增 12，更新 340，可能已删除 3，已删除 2，失败 5」，每个数字可点击，跳到用时间范围筛选好的资源列表或任务列表）。扫描状态、扫描记录和任务列表每 5 秒自动刷新一次（可能已删除的资源和异常范围每 15 秒，进行中的扫描详情每 3 秒），正在跑的扫描会自己动起来。

右上角「扫描」按钮打开表单：
- 账号：可以按名称、ID、EIM、BA 搜索多选，或选「全部账号」。
- 区域、类型：默认全部。
- 提交按钮上方写明范围：「将扫描 12 个账号，4 个区域，14 种资源类型」。超过 50 个账号时在按钮旁说明「一次最多 50 个账号，可以选择全部账号」，按钮不可用。

### 3.6 扫描详情、任务详情
- 扫描详情：状态、范围、结果数字、按原因分组的失败、任务列表；「重试失败的任务」「取消」（不二次确认）。
- 任务详情：任务信息、错误说明，以及直接显示的日志（来自 `GET /tasks/{id}/logs`，可以加载更多）。取不到日志（接口返回 503，本地环境一定如此，因为 moto 里没有日志组）时，只显示一行「日志暂时无法查看」，不当作错误弹出。

## 4. 状态处理

| 状态 | 处理 |
|---|---|
| 加载中 | 表格和数字用占位骨架；超过 300 毫秒才显示 |
| 没有数据 | 一句话说明，加上下一步可以做什么，比如「没有符合条件的资源」+「清除筛选」 |
| 请求失败 | 在对应区块里用一行文字说明，提供「重试」；不弹全局错误框 |
| Redis 不可用 | 无感知，只是计数慢一些 |

## 5. 用词

| 动作或概念 | 中文 | English |
|---|---|---|
| 实时更新单个资源 | 刷新 | Refresh |
| 对账号或范围重新采集 | 扫描 | Scan |
| 下载数据 | 导出 | Export |
| `account_type` | 环境：开发 / 预发布 / 生产 | Environment: Dev / Pre-prod / Prod |
| `missing` | 可能已删除 | May be deleted |
| `deleted` | 已删除 | Deleted |
| 范围超过 12 小时没有成功扫描 | 数据过期 | Out of date |
| `access_denied` | 没有读取权限 | No read access |
| `credential_error` | 无法获取凭证 | Can't get credentials |
| `partial` | 部分无权限 | Partial access |
| 时间 | 3 分钟前（悬停显示具体时间；超过一天直接显示日期） | 3 min ago |
| 数字 | 128,430 个资源 | 128,430 resources |

EIM、BA、ARN 以及 AWS 的类型名、字段名保持原样。英文文案按英文用户的习惯重写，不逐字翻译。

## 6. 外观与交互原则
- 每页一个主色；不用橙色、赤陶色、老式后台的亮蓝色；灰色全部是暖灰；配色从中国传统色里选，已实现三套方案（黛绿、黛蓝、胭脂，见 1.3），用 `?palette=` 切换，对比度都满足 WCAG AA（见 `frontend/PALETTES.md`）。
- 每页最多四种字号；行高、字间距、段落间距统一调校；对比度满足 WCAG AA。
- 等宽字体只用于 ID、ARN、代码和数值；不用斜体；按钮和标签不用全大写；少用中间点（·）连接内容。
- 全产品每个动作只用一个动词（见第 5 节）；不用催促式的动词。
- 页面扁平：不叠加阴影，不用发光和毛玻璃；只有真正浮在页面上的对话框和菜单才有阴影；不在卡片里套卡片；嵌套圆角同心（内圆角 = 外圆角 − 间距）。
- 按钮、间距、圆角、分隔线、对话框、动画保持一致和克制。
- 只有不可撤销的操作才二次确认；不用大面积的红色。
- 界面已经说清楚的，不再加说明文字；必须加提示时，只用一句短话。
- 多语言：布局按最长的译文设计，可以改写文案，不缩小字号、不截断。
- 在用户实际使用的屏幕尺寸上逐一检查（主要是 1440 和 1920 宽的桌面显示器）。
