# 规格：Dashboard

本文是 [DESIGN.md](../DESIGN.md) 第 9 节的实现细节。

## 1. 技术与结构

- React 19、Vite、TypeScript、TanStack Router（文件路由）、TanStack Query、TanStack Table、shadcn/ui（Radix，用到 dropdown-menu、popover、dialog 等几个组件，源码在 `src/components/ui/`）、Tailwind v4、zod（校验 URL 查询字符串）、Biome。表单（扫描表单、筛选）都是简单的受控组件，没有用 react-hook-form。
- Playwright 已接入，端到端测试在 `frontend/e2e/`，覆盖概览、资源筛选和导出、资源详情和刷新、发起扫描、账号覆盖表、语言和主题。本文新增的交互在实现时补进这些测试。
- API 客户端由 `@hey-api/openapi-ts` 根据后端导出的 OpenAPI 生成到 `src/client/`，不手改。接口有变化时：`cd backend && uv run python scripts/export_openapi.py`（写出 `frontend/openapi.json`，需要设置 `DATABASE_URL` 和 `DATABASE_SCHEMA`），再 `cd frontend && npm run generate-client`。导出时把 FastAPI 生成的 operationId 缩短成函数名。
- 构建产物由后端的 `app.frontend(<BASE_PATH>, directory=…, fallback="index.html")` 托管（目录由 `FRONTEND_DIST` 指定，默认是镜像里的 `/app/frontend/dist`，本地是 `frontend/dist`）。路径前缀在构建时由 `BASE_PATH` 决定（Vite `base`，默认 `/aws-inventory`），路由和 API 客户端都用 `import.meta.env.BASE_URL`；开发时 Vite 把 `/aws-inventory/api` 代理到后端（`API_URL`，默认 `http://localhost:8000`）。

### 1.1 路由

| 路径 | 页面 |
|---|---|
| `/` | 概览（Overall） |
| `/resources` | 资源列表；`s=app:<EIM>` 或 `s=acct:<账号ID>` 限定范围；`scanRequestId` 查看某次扫描范围内的当前资源 |
| `/resources/$id` | 资源详情 |
| `/apps` | 应用列表 |
| `/accounts` | 账号列表 |
| `/accounts/$accountId` | 账号详情 |
| `/scans` | 扫描（当前状态 + 扫描记录） |
| `/scans/$id` | 扫描详情 |
| `/tasks/$id` | 任务详情（含日志） |
| `/scan-scopes/$scanShardId` | 待核对的范围 |

- 左侧菜单的服务项不新增路由，指向 `/resources?resourceType=<类型>`；分组指向该组全部类型（重复的 `resourceType`），服务页和分组页只是资源列表的预设筛选。
- 资源列表的 URL 状态：`s`、`scanRequestId`、`q`、`page`、`pageSize`、`sort`、`f`。和默认值相同的不写进地址。

### 1.2 全局布局

- **左侧栏**：产品名、范围切换、Inventory 树（Overall，以及计算、Serverless、网络、消息、安全分组下的服务）、扫描管理、只读说明。当前页面在树里高亮；扫描管理里显示进行中的扫描数量。
- **右侧工作区**：顶栏（全局搜索、语言、身份区）和内容区。
- **范围**：全部应用和账号、单个应用、单个账号。范围只影响资源浏览，不影响扫描管理；切换范围时保留仍然适用的筛选，账号范围下隐藏环境筛选，全局范围下显示应用列。
- **窄屏**：小于 800px 时侧栏收起为抽屉，顶栏保留搜索和身份区；表格在自身容器内横向滚动，不撑破页面。

### 1.3 全局搜索

- 输入 ARN：调用 `GET /resources/lookup?arn=`。只有一条就直接打开详情；多条（共享 AMI）先列出账号让用户选。
- 输入资源 ID：调用 `GET /resources?q=` 做精确匹配。唯一匹配直接进详情，多条进搜索结果。默认只匹配 `active` 和 `missing`；要包含已删除资源时由用户明确选择。
- 输入应用名或 EIM：切到这个应用的范围；账号名或账号 ID：切到这个账号的范围；扫描编号或任务编号：进对应页面；其他内容：进资源搜索结果。
- 顶栏在页面顶部时显示完整搜索框。向下滚动后，搜索框和身份区收成右上角的小胶囊；点击搜索图标时，顶栏原样滑回并聚焦搜索框，滚动位置不变。Esc 或点击顶栏以外的地方关闭，焦点回到搜索图标。`/` 是快捷键。
- 搜索只负责查找和导航，不改变当前的资源筛选，除非结果明确落在某个范围。

### 1.4 多语言和配色

- **多语言**：自己写的一个很小的带类型检查的 i18n（`src/i18n/index.tsx`，约 60 行），没有用 react-i18next：界面只有一组扁平的文案、两种语言、简单的复数，不值得多一个运行时依赖。文案放在 `src/locales/zh-CN.json` 和 `en.json`，键在编译时检查，两个文件的键必须完全一致；插值写 `{name}`，数字自动加千分位；文案里用 ` | ` 分隔单数和复数（英文用）。后端返回的错误按 `code` 找 `error.<code>` 文案，找不到才用通用文案。
- **配色**：最终使用**胭脂**（`yan-zhi`），暖灰作为全部中性色。黛绿和黛蓝不再作为可选配色，`?palette=` 参数移除；`frontend/PALETTES.md` 里这两套只保留为历史记录。语言和亮色 / 暗色记在浏览器的 localStorage（`locale`、`theme`），`public/theme-init.js` 在页面渲染前先应用，避免闪一下。
- 亮色和暗色都满足 WCAG AA；暗色使用同一组胭脂和暖灰的对应步进，不自动反转。

### 1.5 身份（暂时用假身份）

- 当前设计阶段用前端内置的假身份展示姓名、邮箱和「已登录，只读访问」，登录过期用预览参数模拟；不接真实认证，也不保存会话。
- 生产构建不能带假身份。正式接入前，身份由内网网关（ALB 或平台网关）传入，Dashboard 只显示姓名、邮箱和只读状态；具体请求头由平台确认。没有身份信息时隐藏身份区，不显示占位姓名。
- 登录过期由网关表达。Dashboard 显示一行提示和「重新登录」，跳转网关重新认证；「退出登录」同样跳转网关。Dashboard 不判断权限。
- 所有写操作仍然记录 `X-Caller-Id`，dashboard 传 `dashboard`；身份只用于显示，不作为授权依据。授权始终由网络层和只读角色控制。

## 2. 数据表格组件（`components/data-table/`）

资源列表、应用列表、账号列表、扫描记录、任务列表都用这一个组件。

- **列由后端决定**：资源列表调用 `GET /columns`，得到列定义，生成 TanStack Table 的列。应用、账号、扫描记录、任务列表的列在前端写死（它们是固定的小表）。
- **筛选控件按列类型自动生成**：

| 列类型 | 筛选控件 | 查询参数 |
|---|---|---|
| `text` | 输入框（包含匹配） | `attr.<key>=…` |
| `enum` | 多选下拉，选项和数量来自 `GET /resources/facets` | 重复的 `attr.<key>=…` |
| `number` | 最小值 / 最大值 | `attr.<key>.gte` / `.lte` |
| `bool` | 是 / 否 / 全部 | `attr.<key>=true\|false` |
| `datetime` | 开始 / 结束时间 | `.gte` / `.lte` |

- 筛选、排序、分页全部在服务端执行（`manualFiltering`、`manualSorting`、`manualPagination`）。
- 状态全部同步到 URL 查询字符串，可以收藏和分享。请求后端时把 `f` 翻成 API 参数：类型专属列加 `attr.` 前缀（用列的 `scope` 判断，所以和通用列重名的 `status` 不会混淆），范围写成 `.gte` / `.lte`。当前类型不认识的筛选会被忽略，不会让页面报错。
- 可以显示 / 隐藏列、调整列宽（保存在浏览器本地）；表头固定。
- `mono = true` 的列用等宽字体；ID 和 ARN 支持一键复制。

### 2.1 资源表格的呈现

- 列顺序：名称 / 资源 ID、账号、应用（只在全局范围显示）、环境（只在非账号范围显示）、区域、资源类型（只在混合类型时显示）、类型专属列。
- 名称和资源 ID 上下两行；账号名和账号 ID 上下两行；应用名和 EIM 上下两行。账号 ID 和 EIM 旁边有复制按钮，复制不打开预览。
- 所有单元格单行显示，超长用省略号，行高统一；完整值放在 `title`，并可在这行的预览侧栏和详情页看到。列多时表格容器横向滚动，第一列固定在左边，滚动时右边缘渐隐提示还有内容。页面本身不出现横向滚动。
- 点击行打开预览侧栏；点击资源名称进入详情页；Enter / Space 打开预览，Esc 关闭并把焦点还给这一行。不再放单独的「预览」按钮。
- 账号名称链接切换到账号范围，应用名称链接切换到应用范围。
- 状态标记只在不正常时显示：「可能已删除」「已删除」「数据过期」；正常资源不加任何标记。
- 默认不显示已删除的资源；「包括已删除」是状态筛选里的一个选项。

## 3. 页面

### 3.1 概览

- 全局搜索只在顶栏，概览页不单独放大搜索框；进入页面直接看到当前范围的统计。
- 范围相关的统计：资源总数、应用数、账号数（含无法访问的数量）、资源类型数、区域数。限定到应用或账号时只显示相关的项。这些数字不依赖最多 200 个选项的分类计数：资源、类型、区域数，以及筛选后的账号数、应用数都来自 `GET /resources/summary`；全局无筛选时的账号数、应用数分别来自 `GET /stats/overview` 和 `GET /applications`。
- 分布：按服务、按账号（应用范围）、按环境（非账号范围）、按区域，横向条形；点击任意一项跳到筛选好的资源列表。每个面板最多显示 4 项，其余收在「展开全部」后。分布默认收起，展开后查看。
- 当前范围的前若干条资源，链接到完整资源列表。
- 应用入口：全局范围下列出应用，可以搜索；进入后限定该应用。
- 没有无法访问的账号、没有异常时不显示对应提示，不放「一切正常」这类占位文字。

### 3.2 应用列表

- 路径 `/apps`；按应用名、EIM、BA 搜索，按环境筛选。
- 列：应用名、EIM、BA、账号数、环境、资源数；可以按应用名、账号数、资源数排序。
- 点击应用名或整行进入这个应用的资源范围；应用名下面显示 EIM，和资源表格里的应用列一致。
- 只显示有活跃账号的应用；没有 EIM 的账号不在这里出现。

### 3.3 资源列表

- 表格上方一行筛选：当前范围的搜索框、环境（账号范围隐藏）、区域、资源类型（服务页固定类型时不显示）、清单状态、清除筛选、导出。全局范围下的账号、EIM、BA 和标签筛选收在「更多筛选」里，展开后使用；进入应用或账号范围后，对应的账号或应用筛选隐藏。标签支持有、缺少、等于三种写法。
- 导出：选择 CSV 或 JSON Lines，导出符合当前筛选的结果。
- 服务页和分组页是预设了 `resourceType` 的资源列表，顶部显示这一类的数量和按环境、区域的分布；多个类型时用页签切换。
- 扫描范围模式（带 `scanRequestId`）：标题写「扫描 #<id> 的资源」，副标题写明这是该扫描范围内的当前清单，不代表这些资源都在本次扫描中发生了变化；提供返回这次扫描详情的链接。
- 空结果：一句话说明，加上「清除筛选」，不显示空表格。
- 只读：没有编辑、删除资源的操作。

### 3.4 资源详情

- 标题区：资源名称（没有名称时显示资源 ID）、类型、异常状态（如有）、「刷新」按钮。
- 返回链接保留来源：从资源列表进入回列表并保留筛选；从扫描、任务或待核对范围进入，回到对应页面。
- 刷新：调用 `POST /resources/refresh?wait=20`。等待时按钮显示加载状态；202 时显示「刷新中」并轮询任务；失败时在标题区下方用一行文字说明原因（比如「没有读取权限」），不弹框。
- **刷新结果只写回发起时的那条资源**。用户切到别的页面或另一条资源后，结果丢弃，不显示到当前页，也不改变当前页的其他资源。
- 基本信息：ARN（可复制）、账号（名称，下面显示 ID）、EIM（应用名，下面显示 EIM）、BA、环境、区域、首次发现时间。
- 「更新于 3 分钟前」：悬停显示具体时间和来源（「来自 AWS Config」/「实时查询」）。
- 标签：键值表格。
- 关联资源：按关系名分组，点击跳转；库里没有的显示为灰色、不可点击。
- 配置：Config 格式的 JSON 查看器，可以折叠、展开、在其中搜索。
- 实时数据：只有存在 `live` 时显示，标题写明观察时间。
- 属于待核对范围的资源，在标题下方显示一行提示，链接回对应的核对页。

### 3.5 预览侧栏

- 点击资源行打开，作为覆盖在页面右侧的侧栏；背景不加遮罩以外的装饰。
- 内容：类型和名称、资源 ID（名称相同时不重复）、全部类型专属配置、归属（账号、应用、环境、区域）、标识（ARN）。
- 配置按「字段名在左、值在右」排列，值不加粗，不套卡片；账号和应用同样是名称在上、编号在下，和表格一致。
- 底部固定一个「查看详情」，旁边说明关联资源和标签在详情里。
- 侧栏内可以把键盘焦点限制在侧栏里，Esc 关闭并把焦点还给打开它的那一行；点击侧栏外关闭。

### 3.6 账号

- 列表列：名称、ID、环境、EIM、BA、资源数、状态、上次扫描时间。状态只在不正常时显示文字：「没有读取权限」「无法获取凭证」「部分无权限」；已移除的账号显示「12 天后清理」。默认只列活跃账号，勾选「已移除的账号」（对应 `active=false`）才显示被移除的。
- 详情：
  - 基本信息和状态（直接写原因，不显示错误代码）。
  - 区域：已扫描的区域；「已开启，未扫描」的区域单独列出。
  - 「区域 × 类型」格子：每格一种状态（正常 / 失败 / 没有权限 / 数据过期 / 未扫描），悬停显示时间和原因。格子来自 `GET /accounts/{id}/coverage`，没有扫描记录的组合显示为「未扫描」。
  - 「扫描这个账号」按钮：扫描这个账号的所有区域和类型，提交后跳到这次扫描的详情。
- 账号页可以进入这个账号的资源范围，也可以进入它所属的应用。

### 3.7 扫描（管理）

上半部分是当前状态，按排查顺序排列：

1. 全量扫描进度：「已完成 612 / 1,024 个账号，预计 16:40 完成」，下面一条进度条，点击跳到这次扫描的详情；还没有账号完成时没有预计时间，只写「已完成 0 / 1,024 个账号」。比计划慢时显示「比计划慢了」，**不写具体时长**：`GET /scans/summary` 只返回 `behindSchedule`，不返回计划完成时间。
2. 任务积压：按需和定时分开，「排队 34 个，最早的等了 2 分钟」；只显示有排队任务的一行。
3. 最近 24 小时的失败：按原因分组，每组一句白话说明和处理建议（文案见 [scanner.md](scanner.md) 第 9 节），点击跳到**最近一次扫描**（正在跑的全量扫描，没有就是扫描记录里最新的一条）的任务列表，并按这个原因筛选：目前没有跨扫描的全局任务列表接口，任务列表只能在某次扫描下查看。
4. 可能已删除的资源：数量和列表，每行「再检查一次」（调用刷新接口，参数是这条记录的账号、区域、类型和资源 ID），列表放不下时链接到状态筛选为「可能已删除」的资源列表。
5. 数据异常的范围：每行显示范围、检测时间、本次未发现的数量和当前数量，提供「核对资源」进入核对页；「重新扫描」直接为这个范围创建扫描。不再在这里直接放「确认是真实变化」，确认在核对页完成。
   范围较多时分页显示，每页 50 个。

没有问题的区块整个不显示，不放「一切正常」这类占位文字。

下半部分是扫描记录：时间、触发方式（定时 / 手动 / 调用方名称）、范围、状态、结果（「新增 12，更新 340，可能已删除 3，已删除 2，失败 5」）。**结果数字只作为统计，不链接到资源列表**：系统只保存当前状态，无法还原某次扫描当时的新增、更新或删除明细。失败数字可以跳到这次扫描的任务列表并按原因筛选；另提供「查看当前范围资源」，链接到带 `scanRequestId` 的资源列表，并写明是当前清单。

扫描状态、扫描记录和任务列表每 5 秒自动刷新一次（可能已删除的资源和异常范围每 15 秒，进行中的扫描详情每 3 秒），正在跑的扫描会自己动起来。**自动刷新在键盘焦点位于按钮、链接或输入框时不重绘整个列表**，避免用户正在操作的元素被替换；焦点离开后恢复刷新。需要更新时只更新不会夺走焦点的区域。

右上角「扫描」按钮打开表单：

- 账号：可以按名称、ID、EIM、BA 搜索多选，或选「全部账号」。已选账号单独列在上面，可以逐个移除。
- 区域、类型：默认全部。
- 提交按钮上方写明范围：「将扫描 12 个账号，4 个区域，14 种资源类型」。超过 50 个账号时在按钮旁说明「一次最多 50 个账号，可以选择全部账号」，按钮不可用。
- 「全部账号」模式说明这会扫描整个组织，不受当前资源范围限制。

### 3.8 待核对的范围

- 路径 `/scan-scopes/$scanShardId`；从扫描页的异常范围进入。
- 直接打开链接也能找到这个范围：按范围 ID 读取，不依赖先从列表页进入；读取失败时显示错误和「重试」，不显示「找不到」。页面每 15 秒刷新：检测时间或候选变化时重新读取候选并关闭已打开的确认框，异常解除后显示「找不到这个待核对的范围」。
- 标题「核对未发现的资源」，写明账号、区域、资源类型、检测时间、本次未发现的数量和当前范围里的总数。
- 明确写「未发现不等于已删除」：范围保护保留了资源原来的清单状态，没有把它们标为可能已删除；最后一保存的配置仍然保留。
- 候选列表来自触发保护时保存的候选资源 ID（见 [scanner.md](scanner.md) 第 8 节），分页显示名称、资源 ID、ARN、本次未发现、保留的清单状态。可以搜索、分页，点击行打开预览，点击名称进入详情，详情能返回这个核对页。
- 候选资源已经在库里被清理时，只显示资源 ID 和「记录已清理」，不伪造名称。
- 操作：「暂不确认」返回扫描页；「确认是真实变化」打开二次确认，确认框写明「确认后会立即重新扫描这个范围，仍然没看到的资源会逐个按 ID 读取，AWS 明确回答不存在的才标为已删除，读取失败的不算。这一步不能撤回」。确认后调用 `POST /scan-scopes/confirm-change`，跳到新建的扫描详情。
- 没有候选明细时（接口没有返回或候选已清理），显示一句说明和「查看这个范围的全部资源」，不显示空表格。

### 3.9 扫描详情、任务详情

- 扫描详情：状态、范围、结果数字、按原因分组的失败、任务列表；「重试失败的任务」「取消」（不二次确认）。结果数字同样只作统计；「查看当前范围资源」链接到带 `scanRequestId` 的资源列表。
- 任务详情：任务信息、错误说明，以及直接显示的日志（来自 `GET /tasks/{id}/logs`，可以加载更多）。取不到日志（接口返回 503，本地环境一定如此，因为 moto 里没有日志组）时，只显示一行「日志暂时无法查看」，不当作错误弹出。

## 4. 状态处理

| 状态 | 处理 |
|---|---|
| 加载中 | 表格和数字用占位骨架；超过 300 毫秒才显示 |
| 没有数据 | 一句话说明，加上下一步可以做什么，比如「没有符合条件的资源」+「清除筛选」 |
| 请求失败 | 在对应区块里用一行文字说明，提供「重试」；不弹全局错误框 |
| Redis 不可用 | 无感知，只是计数慢一些 |
| 后台刷新 | 焦点在按钮、链接或输入框时暂停整页重绘；焦点离开后恢复。刷新结果只写回发起时的对象 |
| 登录过期 | 显示一行提示和「重新登录」，跳转网关；不清空页面内容，标注内容可能不是最新 |

## 6. 外观与交互原则

- 每页一个主色，最终使用胭脂；暖灰是全部中性色。不用橙色、赤陶色、老式后台的亮蓝色。
- 每页最多四种字号；行高、字间距、段落间距统一调校；对比度满足 WCAG AA。
- 等宽字体只用于 ID、ARN、代码和数值；不用斜体；按钮和标签不用全大写；少用中间点（·）连接内容。
- 全产品每个动作只用一个动词（见第 5 节）；不用催促式的动词。
- 页面扁平：不叠加阴影，不用发光和毛玻璃；只有真正浮在页面上的对话框、侧栏和菜单才有阴影；不在卡片里套卡片；嵌套圆角同心（内圆角 = 外圆角 − 间距）。
- 按钮、间距、圆角、分隔线、对话框、动画保持一致和克制。
- 只有不可撤销的操作才二次确认（v1 只有「确认是真实变化」一处）；不用大面积的红色。
- 界面已经说清楚的，不再加说明文字；必须加提示时，只用一句短话。
- 多语言：布局按最长的译文设计，可以改写文案，不缩小字号。表格内的固定列宽是例外：单元格单行省略，完整值在悬停、预览侧栏和详情里都能看到。
- 在 1440 和 1920 宽的桌面显示器上逐一检查；另检查 1024 和 390 宽，确认侧栏收起、表格横向滚动和对话框不溢出。
